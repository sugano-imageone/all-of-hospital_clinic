この文言を受けたら、本書を読んで構築を開始する。現時点で新しい環境の作成・予約実行はしていない。別PC・新しい会話でも確実に参照できるよう、コードと一緒に本書を保存する。

## 別PCから開始する方法

1. GitHubで `sugano-imageone/all-of-hospital_clinic` の最新コードを開くか、clone/pullする。
2. Codexでこのリポジトリを作業対象として開く。
3. 「すガコン用システムも作って」と入力する。ルートの `AGENTS.md` から本書へ進む。
4. リポジトリを開いていない新しい会話では、以下をそのまま入力する。

> すガコン用システムも作って。GitHubの sugano-imageone/all-of-hospital_clinic にある docs/sugacon-build-handoff.md と AGENTS.md を読み、今回作成した医療機関データベースの「すガコン」版を構築してください。既存のイメージワン環境は維持してください。

別の会話が過去のチャットを自動で参照できるとは限らないため、リポジトリと本書を引継ぎ元とする。新しい会話でGitHub連携・対象リポジトリへのアクセスがない場合は接続する。秘密値は環境設定に登録し、本文やGitへ記載しない。

## 再現する機能

- メールアドレスIDでのログイン、パスワード変更、承認された利用者だけの閲覧。
- 病院／診療所検索、地域・名称・医療機関コード・開設者・病床条件、並べ替え、50件ずつのページ送り。
- 病院検索の初期値は20〜200床。未記載の病床数は0床扱い。通常検索は現存、任意で休止を追加。
- 検索結果のExcel・CSV出力、現存施設の全取得県マスターExcel。
- 管理者・マスター向けの「全医療機関データ出力（CSV）」：全施設・全状態・全列。一般ユーザーには無効表示。
- 集計ダッシュボード、取得元・更新情報。
- 管理者によるユーザー追加・権限／承認管理、ログイン案内のコピー・保存。
- 簡易操作マニュアル（HTML／PDF）、画面上部のリンク。
- 厚生局公式の医科主一覧47都道府県の取得・検証・取込。JST毎月20日開始、25日まで再試行する月次更新。

対象は医科の医療機関。自衛隊病院・歯科大学／歯学部病院・矯正施設等を別目的で追加しない。ナビィ施設番号と保険医療機関コードを混同しない。将来の合併計画だけを現状の変更として登録しない。

## 構築の順序

### 1. 接続先とコードの分離

新システム用リポジトリ／チェックアウトを用意する。認証情報、現行ユーザー一覧、仮パスワード、セッション、ログをコピーしない。既存本番へ書き込む環境変数を流用しない。GitHub／Supabaseの対象を読み取りで確認してから変更する。

Python 3.12以上、Node.js、`requirements.lock`、`web/package-lock.json` を使う。

```bash
python -m venv .venv
# Windowsでは .venv\Scripts\python、macOS/Linuxでは .venv/bin/python を利用
python -m pip install -r requirements.lock
npm ci --prefix web --ignore-scripts --no-audit --no-fund
```

上の `python` は有効化済み仮想環境のPythonを指定する。

### 2. 新環境のDB定義を作成・検証

**既存のSQLファイルを名前順にすべて実行しない。**

- `001_initial.sql` 等の新規スキーマは取込IDがUUID。一方、現行本番の移行後スキーマはbigintで、構造に違いがある。
- `010_upgrade_existing.sql` は既存の特定スキーマ専用。空DBにはそのまま使えない。
- `013_staged_upload.sql` は010適用後のバージョン検査と構造を前提にしている。
- `015_master_role.sql` はイメージワン側の所有者メール・UUIDが固定。新環境へそのまま実行しない。

これらを参照して、新しい空のSupabase用に現行機能一式を持つ導入SQLを作成する。新環境の型に統一し、取込RPC・ステージング・病床同期・履歴・RLS・所有者保護・集計RPCまで含める。新環境専用の所有者IDを使う。

隔離DBで新規作成から取込、重複防止、ロールバック、検索、一般ユーザー制限まで確認する。データAPI用キーではDDLを実行できないため、SQL Editorまたは正規のDB管理接続を利用する。利用可能な接続がなければ、実行用SQLを完成させたうえで操作を依頼する。

### 3. Authと管理者

公開の自由登録は無効にする。新環境の所有者アカウントを作成し、本人指定のメール・UUIDと照合してマスター／管理者として承認する。Supabase Edge Function `supabase/functions/admin-users` を新プロジェクトへ配置し、設定・関数内の対象が新プロジェクトになっていることを確認する。

追加ユーザーは本人から指定された分だけ作成する。仮パスワードは新規に生成する。既存アカウントがあれば登録済みとして確認し、パスワード変更はユーザーの指示に従う。必要な一覧表は非公開・期限付きで本人へ渡し、Gitや公開サイトには含めない。

### 4. ブランド・公開先・マニュアル

主な変更箇所：

- `web/site-settings.json`：ページタイトル。
- `app/templates/index.html`：ヘッダー、運営者、本文、フッター。
- `app/main.py`：アプリタイトル等。
- `scripts/build_pages.py`：サイト設定編集リンクのGitHub所有者／リポジトリ。現在は既存リポジトリのURLが固定。
- `web/public-config.json` またはビルド時環境変数：新SupabaseのURL・公開用キー。
- `app/static/user-guide.html` と `user-guide.pdf`：名称、運営者、ログインURL、日付。PDFを作り直す。
- README・公開設定：新システムのURLと運用情報。

既存の組織名、プロジェクトID、所有者UUID、GitHub名が残っていないか検索する。コードの例・来歴として必要な参照と、実際に接続する設定を区別して確認する。

```bash
python -m scripts.build_pages
```

`artifacts/pages` は静的クライアントのみ。医療機関データ本体・ユーザー一覧・秘密キーを含めない。GitHub Pages用Actionsで公開し、公開URL・ログイン・マニュアル/PDFリンクを確認する。`scripts/publish_pages.py` は別方式（gh-pagesブランチ）なので、Actions公開と二重運用しない。

### 5. データ取得と月次更新

公式配布元の `config/sources.json` と `app/importers/discover.py` 等を使い、対象月・県・コード・件数・重複を検証して、新DBへ取込。月次の検証CLIは `python -m app.importers.monthly`、本登録は `--apply`。更新時は県単位で一括確定し、未公表・失敗分は既存値を維持する。

`.github/workflows/monthly.yml` はUTC `0 * 19-25 * *` で起動し、ワーカーがJST20〜25日だけ処理する。20日の更新完了を保証するものではなく、公表状況とActionsの遅延に依存する。

新リポジトリに以下を設定する。

- Variable：`SUPABASE_URL`。
- Secrets：`SUPABASE_PUBLISHABLE_KEY`、`SUPABASE_SECRET_KEY`。
- 手動実行で `apply=false` の検証、その後 `apply=true` の取込を確認する。
- 正常動作を確認してVariable `ENABLE_MEDICAL_MONTHLY=true` を設定する。
- Workflowがactiveであることに加え、有効化Variable、Secretsの登録有無、ジョブの成功、DBの更新履歴を確認する。参照権限がなく確認できなければ未確認と報告する。

今回のイメージワン環境でもWorkflow自体はactiveだが、有効化Variableは参照APIが403で確認できず、月次自動実行の稼働確認は未完了。これを新環境の稼働確認に流用しない。

## 完成確認と納品

- マスター／管理者／一般ユーザー／未承認／未ログインの各状態を確認。
- 病院・診療所、無床・有床、地域・病床・名称検索の件数を確認。
- 検索CSV/Excel、全取得県マスター、全件CSVを確認。全件CSVは検索条件に影響されず、1,000件を超えて取得できること。一般ユーザーの全件ボタンは無効。
- 全件出力の画面制限と、閲覧者に元来許されている検索・取得権限を区別する。GitHub Pages版は静的クライアント＋RLSであり、ボタン無効化が一般ユーザーのデータ収集そのものを禁止するわけではない。
- ユーザー追加、権限、仮パスワードでのログイン、本人のパスワード変更を確認。
- 月次更新の実行結果、データ取得日、更新元、対象範囲を確認。
- 日本語表示、マニュアルHTML・PDF、配布ファイルのダウンロードを確認。
- 既存イメージワン環境が維持されていることを確認。
- 公開URL、簡易操作マニュアルPDF、本人指定のユーザー一覧、更新設定の確認結果、未完了事項を本人へ渡す。
