# 届出事項の取得・検索・更新検査（開発用）

2026年10月16日。開発専用ブランチ `dev/facility-notifications-research-20261016`。
本番DB、main、公開サイト、本番の月次更新設定は変更していない。

## 実装した内容

- 全8局・支局の全体医科Excel／ZIPリンクを公開ページから自動解決して取得。
- ローカルSQLiteへ全列・全詳細行を保存。医療機関は10桁コードで一意、届出は正式名称を原資料のまま使用。
- 同じExcelの再取込、および内部メタデータやファイル名だけが変わった同内容の再配布を重複登録しない。並行実行もDB制約とトランザクションで保護。
- 同一届出の複数の詳細行、元資料にある完全同一行も元行として保存。通常の届出一覧は親届出1件として集約し、詳細から全元行を参照できる。
- 届出名が空欄で施設だけ掲載されている行も保存し、届出名を推測して作らない。
- 中国四国の配布物には歯科等も混在。医科の10桁コードへ誤変換せず、区分付きの元行として保持。
- 旧版を履歴として保持し、新しい資料は県別スナップショットとして保存。確認済みの最新版だけ検索対象にする。

## 検索画面

加算名・届出名（部分名称可）、**「届出済の」「未届出の」**、診療科目、病院／診療所、都道府県、10桁コード、医療機関名を組み合わせる。

例：施設区分「診療所」、診療科目「整形外科」、加算名「電子的診療情報連携体制整備加算」、届出の有無「未届出の」。この名称の一部で検索する場合、加算１・２・３など、その文字列を含む正式名称をまとめて対象にする。正式名称を全部入力すれば、その文字列を含むものに絞れる。数値の算定実績ではなく厚生局の受理名簿に基づく。

今回のデータでは、この例の届出済7,488施設、未届出4,072施設。地域・科目等の同条件で名簿掲載を照合できない152施設は「未届出」に混ぜない。各施設に届出資料の基準日を表示する。地域によって9月1日／10月1日基準であり、今日の実態を断定しない。

各施設の「全届出」からすべての正式名称を一覧表示し、届出の詳細を開くと全24列・元ファイル・シート・行番号・元資料URLを確認できる。データ取得状況や照合未了を「未届出」と判断しない。

### 診療科目

ユーザー指示によりナビィは使用しない。厚生局の公開主一覧（既存の検証済みローカルデータ）97,457施設を開発用に読み込んだ。診療科目があるのは94,200施設、未記載は3,257施設（うち北海道3,250施設）。未記載は科目指定検索から除外し、施設名から推測しない。

科目の原表記を保存・表示し、略称は[厚生局の公式略称一覧](https://kouseikyoku.mhlw.go.jp/kinki/gyomu/gyomu/hoken_kikan/documents/sinryou-kamoku-itiran.pdf)を参考に検索分類する。例えば「整外」を「整形外科」分類で検索できる。略称一覧は実際の標榜名称を一意に保証するものではないため、原表記を表示する。未対応の表記は推測で補わず元の語をそのまま検索候補に残す。北海道の現在の主一覧は郡市区別帳票で診療科目欄を持たず、別帳票での補完は未完了。

## 更新差分・異常検知

新データを直接上書きせず、まず独立したスナップショットとして保存し、現行版と比較する。

| 検査 | 初期の保留基準 |
| --- | --- |
| 元行数の増減 | 旧版に対し20%超 |
| 届出の追加＋削除 | 20件以上かつ旧届出数の25%超 |
| 施設コードの追加＋削除 | 10施設以上かつ旧施設数の10%超 |
| 全詳細行の追加＋削除（同一行の出現回数を含む） | 50行以上かつ旧元行数の50%超 |
| 基準日 | 将来日なら保留、旧版なら履歴扱いで現行を維持 |
| 官報告示の掲載情報の更新 | 未確認の告示掲載情報があれば、新しいデータへの切替を保留。判断根拠は告示本文・別添 |
| 列・コード・管轄・名称・行数の不整合 | 当該県の取込をロールバック、旧版を維持 |

届出・施設の追加／削除、正式名称の追加／削除、元行・詳細値の増減と割合を確認できる。行数が同じでも中身が大量に入れ替わるケースを検知する。閾値は初期値であり、実際の月次差分の観測を基に調整する。大幅増減をすべて誤りとは断定せず、確認対象として保留する。

保留状態はDBと画面の「取込・重複検査」に表示し、CLIは正常完了として扱わない。旧版で検索を継続でき、候補データと差分は失わない。

### 制度変更の判断基準：厚生労働大臣の官報告示

**最終的な基準は厚生労働大臣の官報告示の本文・別添と施行日。中医協の答申は参考情報であり、最終決定として扱わない。通知だけでも基準変更を決定しない。**

告示番号、公布日、官報の掲載号等、正式資料名、施行日、本文／別添の該当箇所、根拠URLを記録する。経過措置・適用対象も原告示の該当箇所で確認し、公表日と施行日を混同しない。本文・別添と厚生局名簿を照合する。通知等は告示に沿った手続き・取扱いを確認するための補助資料として区別して保存する。

`policy_watch` の対象は、厚労省の令和8年度診療報酬改定の官報掲載事項等が掲載されるページと、その後の改正分の掲載ページの2ページ。中医協総会ページは監視・切替判定の対象から除外した。告示・官報・別添・別表等を含む掲載情報の変更を検知したら確認待ちにする。ページの更新検知を官報告示の内容・法的効力の確認済みとは扱わない。年度が変わる際は監視対象も更新する。

官報の原本サイトは https://www.kanpo.go.jp/ 。この実行環境からの直接取得はプロキシが403を返したため、原本サイトの自動取得は未検証。厚労省に掲載される告示の公式写しと、官報の号・告示番号・公布日・本文／別添を照合する運用とし、原本取得が成功したとは報告しない。監視ページのリンクが変わらず、添付ファイルだけ無告知で差し替わる変更の完全検知も保証しない。

改定による差分を確認・承認するときの `--revision-context` JSON形式（値はすべて実際の官報告示を確認して入力する）：

```json
[
  {
    "type": "官報告示",
    "issuer": "厚生労働大臣",
    "notice_number": "実際の厚生労働省告示番号",
    "title": "告示の正式名称",
    "url": "官報または厚労省掲載の公式写しの実際のHTTPS URL",
    "published_date": "YYYY-MM-DD",
    "effective_date": "YYYY-MM-DD",
    "gazette_reference": "官報の実際の掲載日・本紙または号外の号数等",
    "annex_reference": "本文・別添の実際の該当箇所"
  }
]
```

根拠を登録しても、大幅変動の保留は自動解除しない。答申・通知・将来予定だけの根拠では改定に伴う切替承認を拒否する。現在の基準日までに適用され、公表も済んでいる厚生労働大臣の告示を確認する。これは原資料の確認を記録する仕組みであり、告示・別添をAIが推定して制度ルールを生成する機能ではない。

## ローカルで起動する

既存の仮想環境を利用する。ここでは `python` をその環境のPythonとして記載する。本番用のSupabaseキーは不要で、参照もしない。

```bash
# 全8局の最新全体名簿と告示掲載ページを取得し、ローカルへ取込
python -m app.notifications.cli --fetch

# 厚生局の検証済み公開主一覧を10桁コードで結合（ナビィなし）
python -m app.notifications.reference --directory data/zero-v4

# 開発用の読み取り専用ページ。外部公開はしない
python -m uvicorn app.notifications.devapp:app --host 127.0.0.1 --port 8765
```

確認先：`http://127.0.0.1:8765/`。DB既定値は `data/notifications/development-v2.sqlite`、別ファイルを画面で参照する場合は `NOTIFICATIONS_DEV_DB` を指定する。SQLiteと元資料はGit対象外のdata/、実行ログとレポートはartifacts/へ保存する。画面のDB接続は読み取り専用で、更新操作はCLI側に限定する。

上の主一覧JSONは既存の公開資料から生成したローカルファイルで、新しいチェックアウトには含まれていない。新しい環境では既存の全国主一覧取得・検証手順で生成してから指定する。本番DBの個人ユーザーや認証情報をコピーしない。

定期実行は本番設定へ組み込んでいない。開発で十分確認した後、ユーザーから本番反映の指示を受けて別途適用する。

### 保留した更新の確認・承認

```bash
# 保留中の候補と差分を表示
python -m app.notifications.reviews

# 告示掲載ページの変更だけを再確認
python -m app.notifications.policy_watch

# 公式資料と適用時期を実際に確認した記録を登録
python -m app.notifications.policy_watch --review-event ID --note '確認した公式資料と適用時期・判断の記録'

# 比較後に現行版が変わっていた場合は、先に再比較（これだけでは切り替わらない）
python -m app.notifications.reviews --recompare SNAPSHOT_ID

# 候補と旧版の差分を確認した後だけ、候補の切替を明示的に承認
python -m app.notifications.reviews --approve SNAPSHOT_ID --note '差分を確認した理由' --evidence-url '確認した厚労省公式資料の実際のURL'
```

改定による変更なら承認時にも `--revision-context PATH` を付ける。答申・将来予定だけの根拠では承認できない。比較後に別の版へ更新されていれば承認を拒否し、古い判断で新しい現行版を巻き戻さない。
