# 届出事項ページ：厚生局データの自動取得可否調査

確認日：2026年10月16日（日本時間）。開発専用ブランチ `dev/facility-notifications-research-20261016`。

## 結論

**医科の「届出受理医療機関名簿（全体）」は全8局・支局、47都道府県でExcelを自動取得できる。** 公式サイトから認証なしのHTTP GETで15配布物（Excel2、ZIP13、計90,578,852バイト）を取得し、47都道府県の全医科シートで同一の24列と先頭データ行を読めることを確認した。

ユーザー指定により、主な届出項目に限定しない。全体名簿の全届出種類・全列・全備考行を利用する。施設基準以外の保険外併用療養費等は別配布物もあり、追加資料の収集・解析を別に実装する。

この調査で確認済みなのは配布物の取得、ZIP展開、全県の列構造と先頭行の読み取り。全行の構造化・全国の届出件数集計・既存DBとの全件照合・継続運転の検証は今後行う。「全項目を使う」という要件と、「全行の取込実装が完成した」という状態を区別する。

### ユーザー確定仕様：識別子・全件表示・正式名称

2026年10月16日追加指示：

- 医療機関は**10桁の保険医療機関コードを一意キー**として既存マスターと結合する。名称の類似で別コードへ付け替えない。未一致コードは未一致として残す。
- 1医療機関：複数届出：複数詳細行の関係とする。医療機関コードの一意制約を届出テーブルへ誤って適用しない。届出と詳細の行数を減らさず、全データを反映する。
- 届出一覧の表示名は、厚生局Excelの「受理届出名称」にある正式名称をそのまま使用する。任意の短縮名・AIによる名称生成・意味からの推定で置き換えない。
- 公式の略称対応表で確認できる場合のみ、略称に正式名称を対応させる。局・年度／診療報酬改定の版を保持し、同じ略称が複数名称へ対応するときは決めつけない。正式名称が確定できない場合は確認未了として元表記を保持する。
- 届出名称・番号・日付・詳細値には元ファイル、シート、行番号、資料基準日を付け、画面の表示を原資料で検証できるようにする。公表されていない情報を補完しない。

開発段階の検証では、元の行数と保存行数、施設ごとの届出・詳細の件数を照合し、全詳細行の所属先が追跡できることを確認する。完全重複らしき行も原データでは保持し、一覧の集約単位と元行数を別管理する。全行照合前には全国全件取込完了とは報告しない。

### 正規化で欠落を防ぐ点

- 同一施設・届出名称・受理番号・日付が同じでも、備考だけ違う複数行がある。病棟種別、病床区分、病棟数、病床数、届出区分、算定単価などを別行で保持している。単純な重複削除や、備考見出しをキーにした単一値の辞書化はしない。
- 施設1件に複数の届出、届出1件に複数の詳細行を持てる形にする。元行を全保存してから検索用の親・子情報を生成する。
- 受理番号や受理記号だけを全国共通の一意キーにしない。施設・局・届出名・日付・元の行関係を使用する。
- 保険医療機関番号は7桁の文字列を含む。先頭の0を残し、都道府県と医科区分を用いて10桁へ正規化する。併設番号は別保持し、新しい独立医科施設を自動生成しない。ナビィIDと混用しない。
- 医科の全体名簿にも医科併設歯科に関連する届出がある。届出名に「歯科」が入ることだけを理由に削除しない。全項目という要件を維持する。
- 元資料の未記載・0・該当なしを区別して保存する。既存検索用マスターの「病床未記載は0」という方針を、今回の元資料全項目に一律適用しない。
- 確認したサンプルでは正式な届出名称がExcelの「受理届出名称」に含まれている。全行でもこの列の欠落を検証する。略称対応表は補助資料とし、診療報酬改定の版・受理時点も記録する。

東海北陸の保険外併用療養費は医科6県分のPDFリンクを確認した。富山の実ファイル（64ページ）をHTTP200で取得し、先頭ページのテキストを抽出できた。これは施設基準24列と違う帳票なので、PDF表の行・列・複数ページの対応を追加検証する。全国の補助資料すべての項目抽出が済んだわけではない。

各局の補助資料リンクは `source-link-catalog.json` に保存した。北海道の全体ページから「先進医療」は厚生労働省の別一覧を参照する旨も記載されている。公表名簿で確認できる情報と、提出された届出書・添付書類の全文とは同一ではない。今回対象は公開資料に掲載されている全項目とする。

## 更新の実装方針

- ページの見出し・表・リンク文言から医科「全体」の最新版を解決する。今の資料URLは調査時の証跡であり、将来の日付を推測して固定URLを組み立てない。
- Excel・ZIPを主として取得し、PDFは照合・補助資料用に利用する。今回の全体名簿では全局でExcelがあるため、全件PDF OCRは不要。
- URL・SHA-256・HTTP Last-Modified・取得日時・帳票内の基準日／作成日・局・県・全体／差分種別を保存する。ZIP内の日本語名（CP932等）、ディレクトリ、バックスラッシュを扱う。ZIP内の医科・歯科・薬局を混同しない。
- 列構造・県・件数・文字列コード・行の親子構造を検証する。想定外の列は破棄せず原データに保存し、検証エラーとして確認可能にする。
- 全体名簿の定期取得と直近差分の確認を分ける。九州は全体10日頃、項目別20日頃、直近分は第一開庁日／15日頃と案内されている。東北の直近分は20日／月末予定で、全国一律の日付に固定できない。
- 既存の20〜25日の主一覧更新とは別の開発用ジョブとして作り、公表状況に応じた再試行と未更新表示を行う。本番スケジュールにはまだ組み込まない。

## 開発と本番の分離

- 本番DBへの書込・DDL・本番ユーザー変更は行わない。
- main／gh-pagesへpushせず、公開Actions・本番月次更新・本番Secretsを変更しない。
- 最初はローカルの原ファイル／JSON等で解析する。共有開発DBが必要になったら専用プロジェクトを用意し、本番キーを渡さない。
- 同じ医療機関に紐づける場合も開発用のコピーまたは公開資料の医療機関コードを使う。本番マスターを直接変更しない。
- 将来の本番反映は、開発での確認結果と適用内容を提示し、ユーザーの反映指示を受けてから行う。
