# 閲覧者の利用履歴

2026年10月19日: 今回の本番実装範囲はログイン履歴まで。検索・出力の履歴閲覧は今後の範囲とし、既存の記録処理は維持する。詳細は [リリース記録](production-release-20261021.md) を参照。

2026年10月19日追加仕様。管理者（`admin`）とマスタ（`master`）が閲覧者（`user`）の利用履歴を確認できるようにする。本番DB・公開画面への反映は未実施。

## 対象と表示内容

対象は、この医療機関検索ツール内で認証済みの閲覧者が行った操作とする。

| 操作 | 確認できる内容 |
| --- | --- |
| ログイン | 利用者、ログイン日時 |
| 医療機関検索 | 利用者、検索日時、検索条件、検索結果件数 |
| CSV・Excel出力 | 利用者、出力日時、出力形式、対象の検索条件、出力件数 |

日時は日本時間で表示する。閲覧者別・期間別・操作種別で絞り込み、日時の新しい順に表示する。検索条件には、届出事項の利用ON/OFF、ONの場合の正式な届出項目名と「届出済の／未届出の」も含める。OFFの場合、画面に残っているだけの届出条件を適用済みの条件として記録しない。

ログイン日時から滞在時間や作業時間を推測しない。パスワード・認証トークン・出力ファイルの全内容は履歴へ記録しない。出力履歴はシステムでの出力生成を示すものとし、端末への保存完了まで確認できたとは表示しない。

## 利用方法と権限

- 「利用者管理」の中に「利用履歴」を設け、管理者・マスタが開いたときに取得する。通常の検索フォームには表示しない。
- 一般の閲覧者にはメニューを表示せず、API・DB側でも他の閲覧者の履歴を取得できないようにする。管理者・マスタの権限は、その都度サーバー／DBで認証済みの所属情報から確認する。
- 管理者・マスタが確認する対象は閲覧者の利用履歴とする。管理者自身の管理操作、パスワード変更等の記録を閲覧者の利用履歴へ混在させない。
- 表示はページ分割し、条件に該当する記録がない場合はその旨を表示する。画面上で履歴の書き換え・削除を行う機能は追加しない。

この利用履歴は、厚生局データの取得ログとは別の機能である。取得ログは従来どおり、マスタ権限者から求められたときだけ確認し、フォーム・管理画面への取得ログ表示は追加しない。

## 既存の記録と追加実装

既存コードには `access_logs` と `record_access` があり、認証済み利用者の検索・出力を記録する処理がある。これらを利用し、履歴の絞り込み・閲覧権限確認・日本時間表示を実装する。過去に残っている項目だけを過去の履歴として扱い、記録のない検索条件や日時を補作しない。

現行のアプリのログイン処理には `access_logs` への記録がないため、認証・利用承認を確認できたログインを記録する処理を追加する。閲覧者を識別する権限情報の保存方法と保存期間は本番反映前に決める。今後追加する記録項目について、過去分も取得できると表示しない。検索結果の再描画やファイル生成の内部通信を、利用者が新たに行った操作として重複記録しない。
