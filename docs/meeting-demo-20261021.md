# 10月21日 会議用デモ

検索、届出事項による絞り込み、8局・支局のデータ基準日、閲覧者のログイン履歴を操作できるオフラインデモ。会議ではログイン履歴までを確認し、その後の改修は要望に応じて進める。

## 会議での流れ（約5分）

1. 会議用ZIPをすべて展開し、「はじめに.html」をChromeまたはEdgeで開く。
2. `viewer@example.invalid` / `DemoViewer2026!` でデモにログインする。
3. 福岡県・病院・20～200床で検索し、検索欄直下の基準日を確認する。
4. 届出事項をONにして「医療安全対策加算１」を正式名称の候補から選び、「届出済の」「未届出の」を切り替える。OFFに戻すと届出条件は適用しない。
5. 必要に応じて検索結果をCSV・Excelへ出力する。
6. ログアウト後、`admin@example.invalid` / `DemoAdmin2026!` でログインし、「ログイン履歴」から閲覧者のログイン日時を確認する。

これらはファイル内だけで使う架空アカウント。実在の利用者や本番認証情報は含まない。デモのログイン履歴は端末・ブラウザ内に作成され、実際の社内利用者の履歴とは別。操作前に「デモを初期化」で初期状態へ戻せる。

## 収録と基準日

47都道府県の厚生局医科主一覧と、取得済みの医科全届出項目を収録する。中国四国厚生局と四国厚生支局は別々に表示する。医療機関・届出事項それぞれの実際の公表基準日を表示し、取得日を基準日へ読み替えない。取得失敗の注記や取得ログは画面へ追加しない。

医療機関の現存状態は主一覧を使用する。未届出は、表示した基準日の届出名簿に該当項目がない施設を抽出する。最新日付の選択は既存の検証済み索引を使い、同じ日付の受理番号の大小で新旧を推測しない。

## 実運用向けのログイン履歴

未公開の変更として、ログイン履歴の記録・管理者閲覧を実装した。公開サイト・本番DBには未反映。

- `sql/016_login_history.sql`：認証済みセッションIDとAuth側のセッション作成日時から記録する。利用者ID・メール・日時をブラウザから指定して偽装する仕組みにはしない。同じセッションは重複記録しない。
- 承認済み利用者のログイン時に記録する。トークンの更新や画面の再読み込みは新たなログインとして数えない。
- 管理者・マスタは閲覧者としてログインした履歴を、メールアドレス・日本時間の日付で絞り込める。日時の新しい順に50件ずつ表示する。管理者自身のログインは閲覧者一覧へ含めない。
- 閲覧者による履歴取得はAPIとDBの両方で拒否する。パスワード、トークン、実在利用者の履歴をソースやデモへ書き出さない。

本番反映時は、別途の本番反映指示を受けて、対象のSupabaseを確認しSQLを先に適用し、その後にクライアントを配置する。会議用ブランチをmainへマージしない限り、今回の画面変更で本番の公開workflowは起動しない。実Supabaseへの新機能の適用・実アカウントによる動作確認は未実施。

## 再生成

```sh
npm ci --prefix web --ignore-scripts --no-audit --no-fund
python -m scripts.build_meeting_demo \
  --data /path/to/validated/national \
  --notifications /path/to/medical-notifications.sqlite \
  --output work/meeting-demo/package
```

Pythonの依存関係は `requirements.lock`。生成物にはJSZip本体とライセンスを同梱する。通信先や認証キーの設定は不要。

## 検証

```sh
python -m pytest tests/test_login_history.py tests/test_web.py -q
node web/pages.test.mjs
node web/login-history.test.mjs
node scripts/meeting_demo/verify_browser.cjs /path/to/meeting-demo/package
```

ブラウザ試験はPlaywright・Chromiumが必要。検証環境ではローカルHTTPで配信して画面を操作し、外部へのネットワーク要求がないことを確認する。PostgreSQLの権限・日付境界の試験は隔離したPGliteで実行し、本番には接続しない。デモから生成したExcelの行数もCSV・検索結果と照合する。
