# 2026年10月21日会議用の本番改修

## 変更と復旧

- 017は実DBで適用済み、停止フラグtrueを確認。再適用しない。
- 016: ログイン時にSupabase Authの実在セッション・本人・承認を検証して記録。過去の一括登録は行わない。管理者とマスタのみ閲覧者の履歴を参照できる。日本時間の日付範囲・50件のページ分割。既存アカウント・承認・権限を更新しない。
- 018: 追加済みの届出専用テーブル・関数を実DBから取り込み、互換性を保って定義・権限を整備。施設マスタ・Authは変更しない。アップロードは未公開snapshotへ小分けに送信し、局内の県範囲・基準日・件数の検証後にcurrent参照を一つのトランザクションで切り替える。失敗時は公開済みsnapshotを保持。旧snapshotは削除しない。
- 取得原本のURL・SHA256と最新判定の検証記録はwork/notifications-initial内、月次はActions artifactへ保存。届出項目のない施設行はcoverageのみとして保持。
- 検索OFFは既存施設検索を使用。ONは同一のRPCと条件で画面・CSV・Excelを抽出する。取得済み名簿の施設範囲に含まれない施設と、局の名簿で対象項目の掲載を確認できない場合は、未届出の結果から除外する。
- 取得ログのDB閲覧はマスタのみ。画面は追加しない。

問題時はメンテナンスフラグをtrueに維持し、Pagesを前のmainの内容へ戻す。届出の復旧は`notification_current.snapshot_id`を同じ局の以前のvalidated snapshotへ管理接続のトランザクションで戻す（初回は前データがないため参照行だけ削除）。復旧時も施設マスタと利用者テーブルを変更しない。追加テーブル・実在ログは削除せず保持し、依存する画面の復旧を先に行う。

月次は既存施設マスタ更新workflowを維持し、届出専用workflowから既存のSupabase secretsを使用する。20日に全局のDB状態を初期化し成功局を全件切替、25日はDB状態で失敗・未完了の局だけ再取得。20日のDB状態がない場合は停止する。初回投入を20日の成功として扱わない。

## 2026-10-19 本番取込の停止状態

引継ぎ中に別担当がPR #3をmainへ反映したため、その実装を基準に統合した。追加SQLは実DBの既存定義を削除せず整備し、月次の採用切替と成功記録を同じトランザクションにした。既存の取得ログは019でマスタ限定となっていることを実DBで確認した。

本番DBは取込中に `default_transaction_read_only=on` となり、Management APIの `read_only:false` でも書込みが拒否された。`pg_settings`では設定ファイル `/data/pgdata/postgresql.auto.conf` 由来、リカバリ中ではないことを確認。DBサイズは1,337,439,923バイト。容量制限などの管理側通知・プランを確認中であり、制限の強制解除はしていない。

採用済みは北海道厚生局（2026-10-01、41,909届出組）と東北厚生局（2026-09-01、58,526届出組）のみ。関東信越114,000/324,674、東海北陸121,500/132,652、近畿75,000/196,648、中国四国63,000/70,636届出組はstagingで非公開。四国・九州は未投入。これらの未公開分を未届出として公開していない。メンテナンスはDB・画面とも維持し、通常利用への再開は未実施。

残作業はDBの書込可能化の確認、全局取込、実データと認証済み権限による本番確認、Pages公開確認、最後のメンテナンス解除。ローカルの正式な検証済み原本と索引は `work/notifications-initial/` に保持。未公開snapshotのIDを確認し、同じsnapshotへのupsertで再開する。採用済みの局を初回取込のために空にしない。
